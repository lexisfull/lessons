### [349. Intersection of Two Arrays](https://leetcode.com/problems/intersection-of-two-arrays/) · Easy

- **Решение:** [IntersectionTwoArrays.java](src/IntersectionTwoArrays.java)
- **Алгоритм:** HashSet.
- **Задача:** найти общие уникальные элементы двух массивов.
- **Подход:** сохраняем элементы первого массива в HashSet, затем проверяем элементы второго. `remove()` исключает повторное попадание числа в результат.
- **Сложность:** O(n + m) по времени в среднем, O(n + k) по памяти.


### [66. Plus One](https://leetcode.com/problems/plus-one/) · Easy

- **Решение:** [PlusOne.java](src/PlusOne.java)
- **Алгоритм:** Array Traversal + Carry (перенос разряда).
- **Задача:** увеличить на единицу неотрицательное целое число, представленное массивом десятичных цифр.
- **Подход:** проходим массив справа налево. Если текущая цифра меньше `9`, увеличиваем её на единицу и сразу возвращаем массив. Если равна `9`, заменяем её на `0` и переносим единицу в следующий разряд. Когда все цифры были девятками, создаём массив на один элемент длиннее и записываем `1` в начало; остальные элементы остаются нулями.
- **Сложность:** O(n) по времени в худшем случае. Дополнительная память — O(1), если длина числа не увеличилась, и O(n), если нужен новый массив.
- **Особенность:** массив `int[]` в Java изначально заполнен нулями, поэтому при увеличении числа вида `[9, 9, 9]` копировать старые цифры в новый массив не требуется.

## Два указателя

### [15. 3Sum](https://leetcode.com/problems/3sum/) · Medium

- **Решение:** [S3Sum.java](src/S3Sum.java)
- **Алгоритм:** Sorting + Two Pointers; альтернативный подход — HashSet.
- **Задача:** найти все уникальные тройки элементов массива, сумма которых равна нулю. Индексы трёх элементов должны быть различными.
- **Подход:** сначала сортируем массив. Затем фиксируем первый элемент `nums[i]` и ищем пару с противоположной суммой двумя указателями `left = i + 1` и `reight = nums.length - 1`. Если сумма трёх чисел меньше нуля, сдвигаем левый указатель вправо; если больше — правый влево. При нулевой сумме добавляем тройку в результат и сдвигаем оба указателя. Для удаления повторяющихся троек используется `HashSet<List<Integer>>`.
- **Альтернативный подход:** для каждого фиксированного элемента искать недостающее число через `HashSet`, проверяя, встречалось ли оно среди уже просмотренных элементов. Такой вариант также имеет среднюю временную сложность O(n²), но требует дополнительной памяти для множества.
- **Сложность:** O(n²) по времени, O(k) дополнительной памяти для множества из `k` уникальных троек (без учёта памяти сортировки и возвращаемого списка).
- **Особенность:** в отсортированном массиве дубликаты можно пропускать непосредственно при движении указателей — тогда отдельный `HashSet` для результата не нужен.

### [11. Container With Most Water](https://leetcode.com/problems/container-with-most-water/) · Medium

- **Решение:** [ContainerWithMostWater.java](src/ContainerWithMostWater.java)
- **Алгоритм:** Two Pointers.
- **Задача:** найти две вертикальные линии, которые вместе с осью X образуют контейнер, вмещающий максимальное количество воды.
- **Подход:** устанавливаем `left` в начало массива, а `reight` — в конец. Вычисляем площадь как `Math.min(height[left], height[reight]) * length` и обновляем максимум `res`. Сдвигаем указатель со стороны меньшей высоты; при равных высотах — правый. Более высокая граница не увеличит площадь при прежней меньшей высоте и сокращении ширины. После каждого шага уменьшаем `length` на один: она всегда равна `reight - left`. Возвращаем максимальную найденную площадь.
- **Сложность:** O(n) по времени, O(1) по памяти.

Для пустого массива возвращаем `0`, иначе — `left + 1`. Первые элементы массива до возвращённой длины содержат уникальные значения.

## Бинарные деревья

### [104. Maximum Depth of Binary Tree](https://leetcode.com/problems/maximum-depth-of-binary-tree/) · Easy

- **Решение:** [MaximumDepthOfBinaryTree.java](src/MaximumDepthOfBinaryTree.java)
- **Алгоритм:** Iterative DFS (Depth-First Search) + два стека через `ArrayDeque`.
- **Задача:** найти максимальную глубину бинарного дерева — количество узлов на самом длинном пути от корня до листа.
- **Подход:** если корень отсутствует, возвращаем `0`. Иначе помещаем корень в стек узлов, а глубину `1` — в параллельный стек глубин. На каждом шаге извлекаем узел и соответствующую ему глубину, обновляем максимум и добавляем существующих потомков с глубиной на единицу больше. После обхода возвращаем максимальную найденную глубину.
- **Сложность:** O(n) по времени, где `n` — количество узлов дерева; O(h) дополнительной памяти в худшем случае для двух стеков, где `h` — высота дерева.
- **Особенность:** оба стека должны изменяться синхронно, чтобы каждому узлу соответствовала правильная глубина. При добавлении правого потомка перед левым левое поддерево обрабатывается первым из-за принципа LIFO; на величину максимальной глубины порядок обхода не влияет.

### [5. Longest Palindromic Substring](https://leetcode.com/problems/longest-palindromic-substring/) · Medium

- **Решение:** [LongestPalindromicSubstring.java](src/LongestPalindromicSubstring.java)
- **Алгоритм:** Expand Around Center (расширение от центра).
- **Задача:** найти самую длинную подстроку, которая одинаково читается слева направо и справа налево.
- **Подход:** перебираем все позиции строки как возможные центры палиндрома. Для каждой позиции расширяем границы в двух вариантах: от одного символа `(i, i)` для нечётной длины и от двух соседних `(i, i + 1)` для чётной. Пока символы на границах совпадают, расширяемся и обновляем индексы самого длинного найденного палиндрома.
- **Сложность:** O(n²) по времени, O(1) дополнительной памяти (без учёта возвращаемой строки).
- **Особенность:** необходимо проверять оба типа центров, иначе можно пропустить палиндромы чётной длины.

### [150. Evaluate Reverse Polish Notation](https://leetcode.com/problems/evaluate-reverse-polish-notation/) · Medium

- **Решение:** [EvaluateReversePolishNotation.java](src/EvaluateReversePolishNotation.java)
- **Алгоритм:** Stack (LIFO) через `ArrayDeque` + Switch Expression.
- **Задача:** вычислить значение арифметического выражения в обратной польской записи, где операторы записываются после операндов.
- **Подход:** последовательно читаем токены. Числа преобразуем через `Integer.valueOf()` и помещаем в стек. При встрече оператора извлекаем два значения: сначала `num2`, затем `num1`; вычисляем `num1 + num2`, `num1 - num2`, `num1 * num2` или `num1 / num2` и возвращаем результат в стек. После обработки всех токенов в стеке остаётся ответ.
- **Сложность:** O(n) по времени, O(n) по дополнительной памяти для стека, где `n` — количество токенов.
- **Особенность:** порядок извлечения операндов важен для вычитания и деления. Деление целых чисел в Java выполняется с усечением к нулю.

### [844. Backspace String Compare](https://leetcode.com/problems/backspace-string-compare/) · Easy

- **Решение:** [BackspaceStringCompare.java](src/BackspaceStringCompare.java)
- **Алгоритм:** Stack (LIFO) через `ArrayDeque`.
- **Задача:** сравнить две строки после обработки символов `#`, где каждый `#` удаляет предыдущий символ, если он есть.
- **Подход:** отдельно обрабатываем каждую строку с помощью стека. Обычные символы добавляем через `push()`, а при `#` удаляем верхний элемент через `pop()`, если стек не пуст. Затем сравниваем размеры стеков и попарно извлекаем оставшиеся символы. Если хотя бы одна пара различается, возвращаем `false`; иначе строки эквивалентны.
- **Сложность:** O(n + m) по времени и O(n + m) по памяти, где `n` и `m` — длины строк.
- **Особенность:** удаление из пустого стека нужно пропускать, а при сравнении возвращать `false` только если символы **не совпадают**.

### [3. Longest Substring Without Repeating Characters](https://leetcode.com/problems/longest-substring-without-repeating-characters/) · Medium

- **Решение:** [LongestSubstringWithoutRepeatingCharacters.java](src/LongestSubstringWithoutRepeatingCharacters.java)
- **Алгоритм:** Sliding Window + HashSet.
- **Задача:** найти длину самой длинной подстроки без повторяющихся символов.
- **Подход:** храним символы текущего окна в HashSet. Если очередной символ уже есть в множестве, удаляем символы с левого края и сдвигаем `left`, пока повтор не исчезнет. Добавляем новый символ и обновляем максимальный размер окна.
- **Сложность:** O(n) по времени в среднем, O(min(n, A)) по памяти, где A — размер алфавита. Каждый символ добавляется и удаляется не более одного раза для каждой позиции строки.

### [438. Find All Anagrams in a String](https://leetcode.com/problems/find-all-anagrams-in-a-string/) · Medium

- **Алгоритм:** Sliding Window фиксированной длины + Frequency Array.
- **Задача:** найти все начальные индексы подстрок `s`, являющихся анаграммами строки `p`.
- **Подход:** создаём два массива частот на 26 букв: для `p` и первого окна строки `s` длиной `p.length()`. При сдвиге окна уменьшаем частоту уходящего символа и увеличиваем частоту входящего, затем передвигаем оба указателя. Если `p` длиннее `s`, возвращаем пустой список.
- **Сложность:** O(n) по времени при фиксированном алфавите из 26 букв, O(1) дополнительной памяти без учёта результата.
